Move this stack to another machine.

OLD machine
  make postiz-export        # DB (channels + OAuth tokens, post history) + posted_log
  make tunnel-down          # stop cloudflared + trigger. NOT scheduler-down (deletes GCP jobs)
  make down

NEW machine
  1. Copy the 3 sibling repos (soljet-postiz, catalyst-knowledge-graph, arboryx.ai), or clone them.
  2. Copy these by hand — gitignored, so a clone has none of them:
       .env
       auth/
       products/arboryx.ai/handles.yaml
       data/postiz_export/                        (from the export above)
       ../arboryx.ai/dev-utils/service_account.json
  3. echo 'export GOOGLE_APPLICATION_CREDENTIALS="<path to service_account.json>"' >> ~/.bashrc
  4. Install Docker + Compose. Fix absolute paths in .env if the mount layout differs.
  5. make venv
  6. make postiz-import
  7. make deploy
  8. make tunnel-up
  9. Verify: make post-status && make social-schedule && make tunnel-check

Nothing to change on GCP — same tunnel hostname, the jobs just hit the new machine.

Gotchas
- Never run both machines against the same channels: two posted_log.sqlite files
  diverging = the same catalyst posted twice on live accounts.
- postiz-import refuses if the target DB already has posts (the dump is --clean
  --if-exists and would drop them). FORCE=1 to insist.
- make down / tunnel-down only stop containers — volumes survive. Only
  `docker compose down -v` destroys the tokens.
- trigger.arboryx.ai/run needs the Bearer SCHEDULER_TRIGGER_TOKEN (it's in .env).
- Redis needs no export.
